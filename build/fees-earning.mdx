title: "Fees & Earning"
description: "Protocol fees and how integrators earn."
---

Two things happen on a swap: Mayan takes a protocol fee, and if you set a referrer address, you take one too.

## Protocol fee

Swift charges **3 basis points (0.03%)**. The live value for any quote is returned as `protocolBps` in the quote response, so read it rather than hardcoding it. It can change at the guardian's discretion.

## Relayer fees

Route-dependent, and returned per quote:

| Field | Notes |
| --- | --- |
| `solanaRelayerFee` | Denominated in the input token on `WH`, in USDC on `MCTP`, and zero on `SWIFT`. |
| `redeemRelayerFee` | Denominated in the output token on `WH`, in USDC on `MCTP`, and zero on `SWIFT`. |
| `refundRelayerFee` | Charged only if the order is refunded. |
| `clientRelayerFeeSuccess` | Total dollar value of relayer fees if the swap succeeds. |
| `clientRelayerFeeRefund` | Total dollar value if it refunds. |

Show `clientRelayerFeeSuccess` if you display a cost breakdown. It is already the aggregate.

## Earning as an integrator

Set a `referrer` address and a `referrerBps` on the quote, then pass the matching `referrerAddresses` at swap time. The fee is collected onchain automatically, with no invoicing and nothing to reconcile.

```typescript
const quotes = await fetchQuote({
  // ...
  referrer: "YOUR_SOLANA_ADDRESS",
  referrerBps: 5,
});
```

`referrerAddresses` is keyed by network type, because the address that receives the fee depends on which chain it settles on:

```typescript
{ evm: "...", solana: "...", sui: "..." }
```

### Splitting across wallets

Pass a `referrers` object to `fetchQuote` instead, with a bps share per wallet, then pass the same object at swap time. The SDK throws if it does not match the quote. See [SDK](/build/sdk).

  **This page is incomplete.** It needs the following from engineering and BD:

  - **The ceiling on `referrerBps`.** Whether there is a maximum, and what happens if an integrator sets something above it.
  - **Which chain the referrer fee is paid on, and when.** Swift v2 changed this: fees moved from the output token on the destination chain to the locked source assets on the source chain. That is a behavioural change for anyone who integrated against v1, and it is not documented anywhere an integrator would find it.
  - **How `referrerBps` interacts with the protocol fee.** Additive on top, or taken from the same pool.
  - **Whether the fee is charged on refunds** or only on completed swaps.
  - **Payout mechanics.** Per swap or batched, and whether there is a minimum before anything moves.
  - **Whether the Referrer Program has terms** an integrator has to accept, given the old Referral Program page framed it as a program rather than a parameter.
